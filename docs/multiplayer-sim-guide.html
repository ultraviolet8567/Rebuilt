Sphinx Match Night

Six people, six computers, one field. Each player drives Sphinx from home with the team's real robot code, in a shared 3-versus-3 match on the 2026 REBUILT field. This guide gets you from nothing installed to playing a match.

Players (six)

Install two things once, then on match night double-click one file and open one link. No programming.

Host (one)

Usually a mentor. Runs the match server on a Mac and sends each player a link. The host can also play.

How it works

Every player runs two things on their own computer: the robot program (the same Java code that runs on Sphinx, in simulation mode) and a Chrome tab with the field. The tab does the physics for your robot and sends your controller to your robot program. The host's computer passes positions between all six tabs so everyone sees the same match.

Player setup (once, about 30 minutes)

You need a Windows 10/11, Mac, or Ubuntu (22.04 or newer) computer with 8 GB of memory or more, Google Chrome or Microsoft Edge (on Ubuntu, the built-in Firefox also works), and an internet connection. A game controller (Xbox or PlayStation style) is best; a keyboard works too.

  1. Install WPILib 2026. This is the free FRC programming kit; it includes the Java that the robot program needs. Download the installer for your computer from github.com/wpilibsuite/allwpilib/releases (the newest 2026 release: the .iso for Windows, the .dmg for Mac, the Linux .tar.gz for Ubuntu), run it, and accept the installer's defaults. The download is about 2.5 GB and the WPILib server can be slow, so start it a day or two early. Installing takes 10–15 minutes.
    Ubuntu: double-click the .tar.gz to extract it, open the extracted folder, and run WPILibInstaller. On an ARM computer use the LinuxArm64 file.
  2. Get the robot code. On Windows or Mac, install GitHub Desktop and clone ultraviolet8567/Rebuilt (File → Clone repository → URL). Then use Current Branch to switch to the simulation branch your mentor names (for now it is claude/multiplayer-shooter-sim-5f688a).
    Ubuntu: GitHub Desktop has no Ubuntu version. Open Terminal and paste these two lines; the code lands in a folder called Rebuilt in your home folder.
    sudo apt install -y git
git clone -b claude/multiplayer-shooter-sim-5f688a https://github.com/ultraviolet8567/Rebuilt.git
  3. Start the robot program once to finish installing. In the code folder, open the sim folder and double-click Start Robot Sim (Mac).command or Start Robot Sim (Windows).bat. On Ubuntu, right-click Start Robot Sim (Linux).sh and choose Run as a Program (double-clicking only opens it in the text editor). The first run downloads more files and can take several minutes. It is ready when the window prints Robot program startup complete. Close the window.
    Mac: if macOS says the file cannot be opened, right-click it, choose Open, then Open again. Windows: if you see Windows protected your PC, click More info, then Run anyway. Ubuntu: if Run as a Program is missing, open Terminal and run bash ~/Rebuilt/sim/*Linux.sh instead.
  4. Plug in your controller (USB is most reliable) and check it works at hardwaretester.com/gamepad.

Match night

Your host sends each person a link with their station in it, like red2 or blue1. Each station is one robot; three per alliance. Station 1 is on the drivers' left, 2 in the middle and 3 on the right, the same on both alliances.

Any number from one to six can play. Stations nobody takes simply have no robot, so two people can play one-on-one and one person can practise alone. The match server still has to be running somewhere; a host can start it and play alone on the same computer.

  1. Start your robot program. Double-click the Start Robot Sim file and wait for Robot program startup complete. Leave the window open all night.
  2. Open your link in Chrome or Edge (or Firefox on Ubuntu). Make the window wide (landscape). If a cookie box appears, you can click the × to decline. If the browser asks whether this site may access devices on your local network, click Allow: that is how the page reaches your robot program.
  3. Wait for "Ready at red2. Drive!" in the corner (about 30 seconds). The page wiggles your robot's joints briefly while it sets up. Keep the tab in front and visible: a hidden tab stops the physics, and setup will fail. Your view starts from behind your own driver station, as a real driver sees the field; press V to change it (see Camera below).
  4. Press any button on your controller so the browser notices it. Then drive. Before a match you can practise freely; the scoreboard shows at the top.
  5. When the host starts the match, every robot jumps to its starting spot. The first 15 seconds are autonomous: your robot runs its selected auto routine, which is Do Nothing unless someone chose one (see Troubleshooting). Then you drive for the rest of the match. When it ends, robots stop until the next match.
Your starting spot can be close to a wall. Drive away from the wall before you turn, or your bumpers will catch it.

Camera

Press V to step through three views. The page shows which one you are in.

ViewWhat you see
Driver station (start)From behind your own station's glass at eye height, turning to keep your robot in view. This is what you would see at a real event.
Driver station, fixedThe same spot, looking at the middle of the field without turning.
Chase cameraAbove and behind your robot, on your alliance's side. Easier for picking up fuel far away.

The scroll wheel zooms in any view. Pushing up on the stick always moves away from your alliance wall, so the driver-station views match the controls.

Scoring tips

  • Shoot from inside your own alliance zone: the hub's side facing the middle of the field has a backboard that blocks shots.
  • Shots land best from about 3 to 3.6 metres from the centre of your hub: from 3.4 metres, 38 of 40 went in during testing. Closer than about 2 metres, the ball hits the rim.
  • Keep clear of your tower (the climbing structure against your alliance wall) and other robots while you aim. Aiming turns the robot on the spot, and a corner that catches the tower pushes the robot off line.
  • A ball counts as soon as it drops into the hub, even if it gets stuck inside.
  • Hold the trigger until the flywheel is up to speed; fuel only feeds once it is.
  • Sphinx holds up to 40 fuel. Drive through fuel with the intake down and the rollers on.

Host setup

The host needs a Mac that stays on during the session (Ubuntu should also work, but only a Mac host has been tested). Setup is done once in Terminal; after that each session is one command.

Once

  1. Install the tools: Node.js 18 or newer, git and git-lfs, Bun, Rust, and cloudflared (brew install git-lfs cloudflared on a Mac with Homebrew).
  2. Build the site and the relay: in the robot code folder, run tools/synthesis/host/build-site.sh. It downloads a fixed version of Autodesk Synthesis (the free, open-source simulator the field runs in), applies the team's changes, and builds everything into tools/synthesis/host/site. About five minutes.
After pulling new code, run build-site.sh again before the next session (about three minutes). Scoring, the hopper and the camera views live in the site, so players only get fixes once the host rebuilds. Players also restart their robot program after pulling.

Each session

  1. Start the server: tools/synthesis/host/start-host.sh --internet. It prints an https://…trycloudflare.com address and six player links. The address is new every session, so send fresh links each time. Use --internet even when everyone is in one house: without it the links are plain http:// addresses, and browsers may refuse game controllers on those (the keyboard still works).
  2. Send each player their link (Discord works). Or paste the address into the link maker below.
  3. Join first. The first player in brings the field and keeps the score, so the host (or whoever will stay all night) should open their link before anyone else. If that person leaves, the score stops updating for everyone.
  4. Run matches: once everyone shows "Ready", click Start Match in the top bar, check the settings (keep use spawn positions on), and start. Click it again for the next match. Ctrl+C in Terminal ends the session.

Troubleshooting

What you seeWhat to do
"Could not join room"The link is wrong or old, or the host's server is not running. Ask the host for a fresh link.
"Setup failed" or nothing happensCheck the robot program window says Robot program startup complete, then reload the page. Keep the tab visible while it sets up.
"A joint did not calibrate"The tab was hidden or busy during setup. Keep it in front and reload.
Robot does not respond to the controllerPress a button after the page loads. Use Chrome or Edge. Unplug other controllers.
Driving feels rotatedSomeone pressed Back / View. Reload the page; the robot finds its true heading again.
Robot sits still for the first 15 secondsThat is autonomous. To run a real auto routine, open the robot's dashboard (AdvantageScope or Glass, connect to localhost) and choose one under Auto Routine before the match.
The field is choppyClose other programs and browser tabs. In the page's settings (gear icon), choose Low graphics.
"Performance issues detected" and a Settings box opensThe page switched itself to simple graphics because the field was running slowly. Click Accept and carry on.
Scores stopped changingThe first player to join (the score keeper) left. Everyone reloads; the host joins first.
Robot program window shows red errors and closesMake sure WPILib 2026 installed, then try again. Send a screenshot to your mentor.

What's tested

Tested (September 2026)

  • Matches with 1, 2, 3, 5 and 6 robots in one room (on one computer, through the host server and relay), including one-on-one across alliances and a full alliance with no opponents
  • Each player's camera starting behind their own driver station, and V switching views
  • Everyone sees the same robot positions (within 10 cm) and the same score
  • All six robots switch together: autonomous, driving, stopped at the end
  • Driving, intake, hood, collecting fuel, shooting and scoring through the real controls
  • Collected fuel shown in Sphinx's hopper, filling and emptying as it collects and shoots
  • Hub scoring: the scoreboard matched the balls tracked going into the hub (33 of 33 in the last check)
  • Heading stays right after the robot is placed at its station and at match start (earlier builds could leave field-relative driving rotated by 90 degrees)
  • The Mac start file
  • The Windows start file and keyboard driving in Chrome (Windows 11, in a virtual machine, over the home network)
  • The Ubuntu start file (Ubuntu 24.04), started from Files with Run as a Program, and keyboard driving in Firefox (in a virtual machine, over the home network)

Not yet tested

  • Players on separate computers over the internet (the Cloudflare tunnel)
  • The WPILib installers for Windows and Ubuntu (the tests used a separately installed Java 17, which is the part of WPILib the start files use)
  • Whether Chrome asks the "local network" question on every computer
  • A full-length match with six real people

Try a dry run with two or three people before the real night. Known limits: the shooter is tuned for the simulator (the team's real shot table was never fully tuned); close shots miss; balls fired in quick bursts sometimes collide in the air. Fuel held in the hopper is drawn, not simulated: it does not collide, so feeder jams do not happen here.

Built on Autodesk Synthesis (Apache 2.0). Robot model generated from the team's Onshape CAD for Sphinx. Setup scripts and technical notes: tools/synthesis/README.md in the robot code.
