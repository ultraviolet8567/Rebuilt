Windows laptop setup for the DIY Systemcore

Team 8567 · Version 1, 2026-11-23 · Made from the setup of the laptop MSI on that date

This procedure sets up a Windows 11 laptop to build robot code and deploy it to the DIY Systemcore (Raspberry Pi 5 clone) without help from a second computer. The Driver Station step is not yet proven on Windows. See section 8.

1. What the laptop connects to

The laptop uses one Wi-Fi network at a time. Do all downloads and the first build on the school Wi-Fi (sections 3 to 5). Then change to SYSTEMCORE to deploy (section 6).

4. Install the tools (school Wi-Fi)

  1. Double-click the .iso file. Windows opens it as a drive.
  2. Run WPILibInstaller.exe from that drive. Select "Everything" and install for all users.
  3. At the VS Code step, select the download for this computer. The installer gets VS Code 1.116.0 from the internet. If there is no internet, select the existing file VSCode-1.116.0-Windows.zip.
  4. Let the installer complete. The tools go to C:\Users\Public\wpilib\2027_alpha5. The folder name is correct: the alpha-6 installer uses the year name 2027_alpha5.
  5. Run FirstDriverStation-win-x64-2027.0.0-alpha-6.exe. Approve the administrator prompt.
The WPILib 2026 tools in C:\Users\Public\wpilib\2026 stay as they are. Do not set a system-wide JAVA_HOME to JDK 25. The 2026 projects need JDK 17.

On MSI, steps 2 to 4 were not done with the installer window. The files were unpacked to the same folder by hand. That gives the build tools but not VS Code or the shortcuts. Run the installer there to get them.

5. Get the project and do the first build (school Wi-Fi)

  1. Copy the folder systemcore-deploy-test to the laptop, for example to C:\frc2027. The project is on the branch claude/systemcore-diy-discovery-722480 of github.com/ultraviolet8567/Rebuilt. On GitHub, select that branch, then Code > Download ZIP, or use git clone and git checkout.
  2. Make sure that these three files agree with the Windows tools:
    FileNecessary text
    settings.gradleString wpilibYear = '2027_alpha5'
    gradle\wrapper\gradle-wrapper.propertiesgradle-9.4.1-bin.zip in the distributionUrl line
    gradle.propertiesorg.gradle.java.home=C:/Users/Public/wpilib/2027_alpha5/jdk
    The copy in the repository has the macOS values. The copy on MSI has the Windows values.
  3. Open a command window in the project folder and build one time with internet: 
    set JAVA_HOME=C:\Users\Public\wpilib\2027_alpha5\jdk
gradlew.bat build
    The last lines must include BUILD SUCCESSFUL.

The first build must have internet. The installer's offline library store does not have some files that Gradle needs (for example a parent file for gson), and a build with --offline stopped with "Could not resolve" before the online build was done. After one online build, --offline builds work.

6. Connect to the Systemcore

  1. Supply power to the Pi. Wait approximately one minute.
  2. On the laptop, join the Wi-Fi network SYSTEMCORE. The default password is PASSWORD (from the 8567 bench guide). Windows shows "No internet". That is correct.
  3. Open http://172.30.0.1 in a browser other than Brave. The SYSTEMCORE page must load.

Other checks: ping 172.30.0.1 gives replies of a few milliseconds.

7. Deploy and verify

Double-click deploy.cmd in the project folder. If the file is not there, make it with this text:

@echo off
set JAVA_HOME=C:\Users\Public\wpilib\2027_alpha5\jdk
cd /d %~dp0
call gradlew.bat deploy --offline || goto :end
echo Waiting 24 s for the robot service to start...
timeout /t 24 /nobreak >nul
call gradlew.bat ntProbe --offline -ProbotAddress=172.30.0.1
:end
pause
  • The deploy must end with BUILD SUCCESSFUL.
  • The wait is necessary. The robot service on the clone waits approximately 18 seconds for CAN interfaces before it starts the program.
  • The last result line must be RESULT: PASS. The controller runs this build and the counter advances.

This was done on MSI on 2026-11-23, with internet and then with --offline. Both gave PASS.

In VS Code with the WPILib extension, "Deploy Robot Code" runs the same gradlew deploy. That path is not yet tested on Windows.

8. Driver Station

The Driver Station on the Windows laptop did not connect on 2026-11-23. On 2026-11-24 the cause was found: the NI 2026 Driver Station was open at the same time. It held the Driver Station network ports and the connection to the Pi. After the NI Driver Station was closed, the 2027 Driver Station connected, and it enabled a motor test program (systemcore-kraken-test).

Items to check when the Driver Station does not connect, in this sequence:

  1. Close the NI 2026 Driver Station. Only the FIRST Driver Station 2027 can be open. This was the cause on this laptop.
  2. Only one Driver Station can be connected. Quit the Driver Station on all other computers.
  3. Press the spacebar one time at the start-up screen. The Driver Station does not connect before this emergency-stop check. On the Mac, this was the cause of "not connected".
  4. If it still does not connect, put 172.30.0.1 in the team number field. On the Mac, a team number of 0 pointed the Driver Station at a simulator on the same computer.
  5. Make sure that the version is 2027.0.0-alpha-6 (shown in the window title).

Windows Firewall was off on this laptop, so it was not a cause here. On a laptop with the firewall on, permit the Driver Station on public networks. Windows identifies SYSTEMCORE as a public network.

The Driver Station is not necessary for a deploy. It is necessary to enable the robot. When it is connected, gradlew deploy gets the robot address from it.
